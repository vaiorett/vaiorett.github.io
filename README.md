## 更新作品图片

1. 打开网站底部的“作品管理”，选择项目。
2. 添加或替换独立图片，填写说明，调整顺序与封面。
3. 连接 GitHub 后发布，或导出更新文件并交给原聊天继续发布。

图片保留上传的原始文件，不再次压缩。每张最多 8 MB。新图片加入后可以移除现有作品长图；移除只改变展示，不删除仓库中的原始文件。草稿保存在当前浏览器，换设备前请导出。

管理页直接发布使用仅允许本仓库 Contents 读写的精细授权令牌，由用户自行在 GitHub 官方页面创建与保管。令牌只在当前页面内存中使用，不写入草稿、网站、链接或导出文件。发布会检查版本，发生冲突时保留草稿并停止更新。提交成功后仍需等待 GitHub Pages 更新。

### 内容与维护

- `site-data.json`：现有中文项目事实、职责、工具、原作品链接；保持原结构。
- `content/projects.en.json`：对应项目的英文翻译。公司、学校和项目名称为描述性译名，不代表经核验的官方英文名称。
- `content/profile.json`：双语经历、教育与证书，日期与原站一致。
- `scripts/build.py`：共享模板和首页文案，生成两种语言的全部 18 个 HTML 页面与 sitemap。需要 Python 3.12+，无第三方依赖。
- `portfolio.css`：公开作品集的响应式样式；原管理页继续使用原有样式。
- `app.js`：双语筛选提示、邮箱复制、画廊、键盘交互与语言链接状态。

修改文案后运行 `python3 scripts/build.py`，再运行 `python3 scripts/check.py`，将数据、生成后的 HTML 和其他变更一并提交。GitHub Pages 直接托管这些静态文件，不需要安装构建服务。

### 图片管理与英文说明

`manage.html` 保留原有上传、封面选择、排序、草稿、导出及 GitHub 发布流程，并增加 English caption 和 English image description 两个选填字段。现有 8 张总览图已提供英文说明；新图没有英文说明时，英文页面使用通用英文提示与项目名称，不把中文说明直接塞入英文正文。

## 图片发布错误处理修复

本次从用户导出的草稿恢复“赛车场看台与配套空间”的 4 张新增图片，并保留原长图、顺序、文件原始字节与所选封面。新图说明使用用户草稿内容，未改写。

管理页的连接成功提示现在仅确认读取权限，不宣称已验证令牌写入权限。上传请求的等待时间由 25 秒调整为 180 秒，其余请求为 30 秒；错误会区分权限不足、限流、网络失败和超时，并保留失败阶段。不会自动重复写请求，也不会将浏览器内存中的修改误称为已持久保存的草稿。GitHub 写入仍需此仓库的 Contents: Read and write 权限。

已同步发布的相同草稿再次连接时不再误报冲突，真正的并发修改仍会停止发布。新增回归检查：`node tests/gallery-core.test.cjs`，覆盖错误分类、超时、相同/冲突草稿、仅上传引用图片与分支版本检查。

每次运行生成脚本会按画廊数据内容更新脚本版本参数，减少发布后旧缓存造成的显示延迟。浏览器管理页直接发布图片后，已缓存页面仍可能需要重新加载或等待缓存过期。
